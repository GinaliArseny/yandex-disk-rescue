# yandex-disk-rescue

*Сделано в [MetaClinic](https://meta-clinic.ru) — открытый инструмент, бесплатно, MIT.*

Скачивание своих данных с Яндекс.Диска по публичным ссылкам — на NAS, внешний HDD/SSD или этот
компьютер. Качает сотни гигабайт параллельно, проверяет каждый файл по md5, докачивает после обрывов,
а файлы, которые Яндекс в данный момент не отдаёт, заносит в список **временно недоступных** — и для
фотографий сохраняет превью как временную замену. Работает как **skill для ИИ-агентов** (Claude Code и
совместимых) и как обычная утилита.

> Download your own data from Yandex Disk public links to a NAS, external drive or local disk: progress
> web UI, md5 verification, resumable segmented downloads, a list of temporarily unavailable files and
> preview copies as a stand-in for photos that are temporarily unavailable. Agent skill + standalone
> tool, Python stdlib only. Docs are in Russian.

![Веб-интерфейс: табло «скачано / временно недоступно», ссылки и выбор места](docs/screenshot.png)

> ☕ **Пока есть что качать, компьютер не уснёт** — утилита сама запрещает сон (macOS, Linux,
> Windows). Всё скачалось или стоит пауза — запрет снимается. На ноутбуке **не закрывайте крышку**:
> так он уснёт всё равно, и загрузка встанет.

## Зачем

Бывает, что часть файлов на Яндекс.Диске временно не отдаётся: при скачивании они долго не отвечают
или обрываются на середине, а веб-интерфейс Диска их тоже не скачивает. Обычная загрузка папки
в такой ситуации застревает. Эта утилита забирает всё, что доступно прямо сейчас, ведёт аккуратный
список того, что временно недоступно, и позволяет одной кнопкой докачать это позже.

## Как это работает

1. Вы даёте **публичные ссылки** на свои папки или файлы (`disk.yandex.ru/d/…`, `disk.360.yandex.ru/d/…`,
   `yadi.sk/d/…`). Токен и вход в аккаунт не нужны — используется только публичный API Диска.
2. Утилита **обходит папки** и ставит все файлы в очередь: сначала фото и документы, крупные видео
   и архивы — следом.
3. Файлы качаются **параллельно** (по умолчанию 16 потоков); крупные — кусками в 8 соединений.
   Каждый скачанный файл **сверяется по md5** с данными Диска.
4. Если Яндекс файл сейчас **не отдаёт**, утилита не ждёт его бесконечно: через несколько секунд
   отмечает файл как **временно недоступный** с причиной и идёт дальше. Для фото в этот момент
   сохраняется **превью** (подробнее ниже).
5. Сбои связи (сеть, временные ошибки сервиса скачивания) утилита в конце **один раз повторяет сама**.
6. Всё, что осталось недоступным, можно **докачать позже** кнопкой «↻ Повторить недоступные».

Состояние хранится в маленькой базе рядом с программой: остановили и запустили снова — продолжит
с того же места, уже скачанное пропустит.

## Вариант 1. Через ИИ-агента (skill)

Подходит, если у вас есть Claude Code или другой агент, который может запускать команды на вашем
компьютере. Агент сам спросит, куда качать, проверит свободное место, запустит утилиту и откроет
страницу прогресса.

**Установите скилл** (один раз):

```bash
git clone https://github.com/GinaliArseny/yandex-disk-rescue ~/.claude/skills/yandex-disk-rescue
```

Или не устанавливайте, а просто дайте агенту ссылку на этот репозиторий. Готовый пакет `.skill`
для claude.ai — в Releases.

**Попросите**, например так:

> Скачай эти ссылки с Яндекс.Диска на внешний диск: https://disk.yandex.ru/d/… https://disk.yandex.ru/d/…
> Держи руку на пульсе: каждые 10–15 минут проверяй ошибки и скорость, разбирайся с паузами и
> сбоями связи, коротко докладывай мне, что происходит.

Последняя фраза важна: загрузка большого архива идёт часами, и что-то может пойти не так — отключится
шара, моргнёт сеть. Скилл объясняет агенту, на что смотреть и как это чинить, но следить он будет,
только если вы попросите.

> Агент должен работать **на том же компьютере**, что видит ваш NAS или диск (Claude Code в
> приложении или терминале). Облачный чат в браузере до домашнего диска не дотянется.

## Вариант 2. Самостоятельно через терминал

Нужен только Python 3.8+ — на macOS и Linux он уже есть, на Windows ставится с python.org.

1. **Откройте терминал.** macOS: `Cmd+Пробел` → «Терминал». Linux: `Ctrl+Alt+T`.
   Windows: `Win` → «PowerShell».
2. **Проверьте Python:**
   ```bash
   python3 --version
   ```
   Должно быть `Python 3.8` или новее. Если macOS предложит установить «инструменты разработчика» —
   согласитесь. Windows: команда `py --version`; если Python нет — поставьте с
   [python.org](https://www.python.org/downloads/) с галочкой «Add python.exe to PATH».
3. **Скачайте утилиту** — командой ниже или кнопкой *Code → Download ZIP* на этой странице
   (распакуйте в домашнюю папку как `yandex-disk-rescue`):
   ```bash
   git clone https://github.com/GinaliArseny/yandex-disk-rescue ~/yandex-disk-rescue
   ```
4. **Если качаете на NAS или внешний диск — подключите его** (macOS: Finder → `Cmd+K` →
   `smb://адрес-NAS`; Windows: «Подключить сетевой диск» в Проводнике).
5. **Запустите:**
   ```bash
   cd ~/yandex-disk-rescue/scripts && python3 app.py
   ```
   Windows: `cd $HOME\yandex-disk-rescue\scripts; py app.py`. В ответ появится строка вида
   `Интерфейс: http://localhost:8765 · куда можно качать: …`. **Терминал не закрывайте** — пока он
   открыт, идёт загрузка, а компьютер не уснёт. Состояние (`state.db`) и журнал (`server.log`)
   лежат рядом со скриптом — продолжать потом нужно из этой же папки.
6. **Откройте в браузере** http://localhost:8765, вставьте ссылки, выберите «Куда качать» —
   и нажмите «Качать».

Остановить — `Ctrl+C` в терминале. Продолжить — та же команда из шага 5: всё уже скачанное
пропустится, работа продолжится с того же места.

## Что вы увидите

1. **Вставьте ссылки** — одну или пачку, можно вперемешку с текстом.
2. **Выберите «Куда качать»** — утилита сама находит подключённые NAS и внешние диски и показывает
   свободное место. Разным ссылкам можно назначить разные места; поменять потом — «📁 Куда…».
3. **Следите за табло**: скачано / временно недоступно / с превью, скорость и файлы в минуту.
   Ненужные папки можно исключить («Папки → ✕ Исключить»), важные ссылки — поднять «★ В приоритет».

   > ⚠️ **Скорость и «осталось» — СУПЕР ориентировочные.** Они зависят от того, какая доля файлов
   > сейчас доступна (доступный файл приходит за секунды, недоступный — проверяется и откладывается),
   > от вашего интернета, VPN и диска. В нашем прогоне скорость прыгала от 1 до 16 МБ/с, а оценка
   > «осталось» показывала почти 9 часов, когда до конца оставалось меньше 2 (и это вместе с
   > перезагрузкой посередине). Ориентируйтесь на полосу прогресса и число файлов, а не на МБ/с.
4. **«✓ Готово»** — когда очередь опустела, наверху появится итог: сколько скачано, где лежит и что
   делать с остальным.

Если ссылка не открывается (опечатка, сняли с публикации, доступ только приглашённым), в её карточке
будет красная плашка с объяснением. Ошибочно добавленную ссылку убирает «✕» — скачанные файлы
при этом остаются на диске.

## Как читать результат

Каждый файл по ссылке оказывается в одном из состояний:

| На табло | Что это значит | Что лежит на диске |
|---|---|---|
| **Скачано** | Оригинал получен и совпал с Диском по md5 | Файл как на Диске |
| **Временно недоступно, сохранено превью** | Яндекс сейчас не отдаёт оригинал, но отдаёт его превью | `ИМЯ.jpg.preview.jpg` (или `.png`) — уменьшенная копия до 1280 px по длинной стороне |
| **Временно недоступно, без превью** | Сейчас не отдаётся ни оригинал, ни превью (или это не фото — у видео и документов превью бесполезно) | Ничего, либо начало файла в `ИМЯ.part`, если он отдался частично |

**Что такое превью и зачем оно.** Для фотографий Яндекс.Диск хранит отдельные уменьшенные копии —
те самые, что вы видите в сетке файлов и при просмотре в браузере. Иногда оригинал временно не
отдаётся, а превью доступно. Тогда утилита сохраняет превью **как временную замену**: у вас будет
хотя бы картинка в хорошем экранном качестве. Это **не оригинал** — разрешение ниже, метаданных
камеры может не быть. Файл при этом остаётся в списке временно недоступных, и когда оригинал
снова станет доступен, «↻ Повторить недоступные» скачает его и удалит превью.

**Причины в списке временно недоступных** (страница → раздел «Временно недоступные файлы», или файл
`_unavailable.tsv` в папке назначения):

| Причина | Что значит |
|---|---|
| `NO_RESPONSE` | Сервер Яндекса не отдал этот файл за несколько секунд |
| `PARTIAL` | Отдалось только начало файла; оно сохранено в `.part`, остальное докачается при повторе |
| `NO_DATA` | Сервер ответил, но данных не отдал |
| `превью тоже недоступно (434)` | Для этого файла у Яндекса нет превью |
| `HTTP 500 … (временный сбой)`, `Сеть …` | Сбой связи или сервиса — утилита повторит такие файлы сама |

Мы не знаем и не утверждаем, **почему** конкретный файл недоступен, — утилита лишь фиксирует, что
в момент скачивания он не отдавался. Проверить позже — «↻ Повторить недоступные» у нужной ссылки:
проверятся только недоступные, докачается только недостающее.

## Где лежат файлы

```
<место назначения>/
  _unavailable.tsv                — список временно недоступных с причинами (обновляется каждые 30 с)
  <имя папки по ссылке>/
    2019 Дача/IMG_0042.JPG        — скачанный оригинал, сверен по md5
    2019 Дача/IMG_0043.JPG.preview.jpg  — оригинал временно недоступен, сохранено превью до 1280 px
    Видео/VID_0007.MP4.part       — отдалось частично (+ .part.json — план докачки)
```

## Остановить и продолжить

`Ctrl+C` в терминале останавливает, та же команда запуска продолжает с того же места: состояние
хранится в `state.db` рядом со скриптом, уже скачанное пропускается.

Пока есть что качать, утилита не даёт компьютеру уснуть (на странице горит «☕ сон отключён»);
когда всё скачано или стоит пауза — снова разрешает. Крышку ноутбука не закрывайте.

## На каких системах работает

| Система | Статус |
|---|---|
| **macOS** | Проверено в бою: сотни гигабайт, NAS по SMB, внешние диски |
| **Linux** | Должно работать — только стандартный Python, диски находятся через `mount`, сон — через `systemd-inhibit`. Вживую не проверялось |
| **Windows** | Поддержка добавлена (диски по буквам, сетевые диски, запрет сна, запрещённые имена файлов), но **не проверялась** — будем рады отзывам. Очень длинные пути (>260 символов) могут потребовать включить в Windows «длинные пути» |

## Если что-то не так

- **Диск в списке помечен «нет прав на запись», хотя подключён** (macOS) — система не пускает
  процесс к сетевым томам, внешним дискам и «Загрузкам»/«Документам». Запустите утилиту из
  обычного Terminal.app или выберите папку `~/YandexBackup`.
- **«Порт 8765 занят»** при запуске — утилита уже запущена (откройте http://localhost:8765) или
  порт занят другой программой: запустите с другим, `PORT=8770 python3 app.py`.
- **Нажали «Пауза», а что-то ещё качается** — так и задумано: начатые файлы докачиваются, новые
  не берутся.
- **Загрузка сама встала на паузу** — отключился диск или шара. Переподключите и нажмите «▶ Продолжить»;
  файлы, на которых это случилось, вернулись в очередь.
- **МБ/с низкие, а прогресс идёт** — на мелких файлах так и есть, смотрите счётчик «ф/мин»
  (и помните: скорость здесь очень приблизительная).
- **Сетевая шара SMB «зависла»** (macOS, Finder не отвечает) — помогает только перезагрузка; держите
  не больше 32 потоков, утилита по умолчанию бережёт шару.

## Что внутри

| Файл | Что это |
|---|---|
| `SKILL.md` | Инструкция для агента: запуск, HTTP API, наблюдаемое поведение сервиса, особенности окружения |
| `references/yandex-behavior.md` | Форма ответов публичного API Диска, коды ответов, превью, замеры |
| `scripts/app.py` | Сервер: обход ссылок, очередь, загрузка, список временно недоступных, HTTP API |
| `scripts/index.html` | Веб-интерфейс |

Переменные окружения (необязательно): `PORT` (8765), `NAS_ROOT` (место по умолчанию),
`DB_PATH` (где хранить состояние), `LOG_PATH` (журнал, по умолчанию `server.log` рядом с базой),
`HEADERS_TIMEOUT` (5 с — сколько ждать ответа сервера). Потоков по умолчанию 16, меняются на странице.

## Оговорки

- Утилита скачивает только **ваши собственные** данные по публичным ссылкам через публичный API
  Яндекс.Диска и ничего не утверждает о причинах, по которым отдельные файлы временно недоступны.
- Проект независимый и не связан с ООО «Яндекс». «Яндекс» и «Яндекс.Диск» — товарные знаки их
  правообладателя.
